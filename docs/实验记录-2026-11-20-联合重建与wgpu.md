# 实验记录 2026-11-20：联合 CFA 重建与 wgpu 后端

## 一、联合 CFA 多帧重建（已判定：不并入主线）

### 做法
把「多帧 + 拜耳采样」当成一个反问题求解，而不是逐帧拆色再平均：

- 未知量：输出网格上的三通道图 `x(R,G,B)`
- 前向模型：每帧先按该帧 PSF（由逐帧 FWHM 折成 σ）高斯模糊，再按配准变换双线性采样，
  只取该帧该像素位置对应的马赛克通道
- 迭代：Richardson-Lucy（乘性更新，保正），覆盖不足的像素不更新
- 可选：每轮追加一次轻微高斯平滑（当作最简单的正则化）

脚本：`G:/M81/_work/jointcfa2.py`（独立脚本，不接入主流程）

### 实测（M81，G 通道，同区域对照）

| 方案 | FWHM | 高频噪声 σ | 耗时（800×800） |
|---|---|---|---|
| drizzle（基准） | **3.73 px** | **3.29e-5** | ~1.5 min |
| 联合重建，无平滑 | 3.07 px | 3.28e-4（10.0×） | 43 s |
| 联合重建，平滑 0.5 | 5.03 px | 4.72e-5（1.4×） | 44 s |

60 帧版本耗时 150 s，成品比单帧还糊（−34%）。

### 结论
- 无正则化时是「10 倍噪声换 18% 锐度」——典型的过拟合噪声；
- 加平滑后连锐度优势也没了，且仍比 drizzle 噪；
- 要做到有竞争力，需要 TV/Wiener 正则 + 更准的 PSF（含可变 PSF），工作量远超收益，
  而理论上限只有亮度的 √2（色度受拜耳采样限制，提升更小）。

**不并入。** 如果以后要重试，起点是：把 `jointcfa2.py` 的乘性更新换成带正则的
`argmin ||Ax-y||² + λ·TV(x)`，并用 ISTA/FISTA 求解，λ 用噪声水平标定。

## 二、wgpu 跨平台 GPU 后端（分支 C）

### 为什么是 wgpu
- 一份 WGSL 着色器跑 Vulkan（Win/Linux）/ D3D12（Win）/ Metal（macOS）
- 纯 Python 包（`pip install wgpu`），不需要 CUDA Toolkit、不需要编译 Rust
- CubeCL / Rust 方案的代价是「每平台一份编译产物 + 改任何一行都要重编」，不适合本项目的迭代节奏

### 算法：gather 而不是 scatter
- scatter（CPU/CUDA 路径）：每帧把每个源像素按 drop 面积摊到输出像素，需要原子加，边界/旋转会导致覆盖率起伏
- gather（wgpu）：每个输出像素反解到源坐标取样，一个线程写一个像素，天然无原子操作
- 代价：**无法做逐像素排异**（要保留每帧样本才能排异），也**没有实现 CFA 颜色掩膜**
  → 这两点都在日志里明说，并且真 CFA 会自动回退 CPU

### 关键修复：双线性 → Catmull-Rom 双三次
第一版用双线性取样，实测成品 FWHM 比单帧还差 4%（因为平移 0.5px 就等于多糊 0.5px）。
换成 4×4 Catmull-Rom 后：
- 冲激响应（整数对齐）：峰值 1.000、能量 1.000
- 端到端：FWHM 由 −3.9% 变为 **+3.6%**

注意：Catmull-Rom 的相位约定必须是「像素中心在整数坐标」，
即 `bx = floor(sx) - 1`、`t = sx - floor(sx)`；写成 `floor(sx-0.5)` 会让峰值掉到 0.316（= 0.5625²）。

### 速度（RTX 4070 Ti，60 帧 CFA 2× 仅叠加阶段）
| 后端 | 耗时 |
|---|---|
| CPU（6 进程分带） | ~118 s |
| wgpu | **24 s** |
| CUDA（CuPy） | 12 s |

### 后端选择顺序（`gpu=auto`）
1. CuPy 可用 → CUDA
2. wgpu 有可用适配器 → wgpu
3. 否则 CPU

`gpu=wgpu` / `gpu=cpu` / `gpu=gpu` 可强制指定；`DWT_GPU_WGPU=1/0` 可环境变量调试。

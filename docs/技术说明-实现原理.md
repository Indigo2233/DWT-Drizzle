# DWT-Drizzle 技术说明：分区加权如何与 drizzle / Bayer drizzle 结合

> 面向读者：想理解这套软件"为什么这样算"的人。
> 不讲怎么点按钮（那在 `使用说明.md`），只讲流水线、公式、以及关键取舍。

---

## 0. 一句话概括

**它把"每一帧的每一个像素该占多大话语权"算成一张权重场，然后把这张权重场直接乘进 drizzle 的液滴散射里；对彩色相机，液滴尺寸再按拜耳同色格点的间距放大，使四个相位都被真实样本覆盖。**

普通叠加是"先对齐、再按帧平均"；drizzle 是"把每个输入像素的小方块投到输出网格上再累加"。DWT 的贡献是：在累加之前，给每个输入像素乘一个由**清晰度、噪声、吞吐**决定的权重——而这个权重是**逐像素、逐帧**变化的。

---

## 1. 流水线全景

```
 读帧 ──► 曝光归一 ──► 逐帧统计(C/S/T) ──► 配准(求变换) ──► 权重场 W(i, y, x)
                                                                    │
                                                                    ▼
                                         ┌──────────────────────────────────┐
                                         │  分带循环（内存只需一条带）       │
                                         │  对每帧：按 W 加权，把像素"泼"到  │
                                         │  输出网格的液滴里（GPU 原子加）   │
                                         └──────────────────────────────────┘
                                                                    │
                    ┌───────────────────────────────────────────────┤
                    ▼                                               ▼
        分子 Σ(w·v)、分母 Σw  ──► 逐像素加权平均             覆盖计数 cov
                    │                                               │
                    └────────► 排异（逐像素跨帧）◄──────────────────┘
                                        │
                                        ▼
                            去格点 / 补洞 / 裁边 / 写 XISF
```

对应的代码位置：

| 阶段 | 位置 |
|---|---|
| 读帧、曝光归一 | `core/pws.py`（`EXPTIME_REF`、`d *= exptime_ref / t_i`） |
| 逐帧 C/S/T | `core/pws.py` 的清晰度测量与 `[C] [σ] [W]` 日志 |
| 配准 | `core/pws.py` + `core/trireg.py` + `matchref` |
| 权重 | `core/pws.py: strip_weights()` |
| 散射（CPU） | `core/drizzle.py` |
| 散射（GPU） | `core/gpu_wgpu_cfa_fatom.py`（wgpu：Vulkan / Metal / D3D12） |
| 排异 | `core/pws.py` 的 `stack_strip()` / ESD |
| 合成与写盘 | `core/pws.py`（去格点、补洞、裁边、XISF 输出） |

## 2. DWT 的核心：不是"一帧一个权重"，而是"一帧一像素一个权重"

### 2.1 为什么全局加权不够

一帧照片里，星云细节需要**锐**（解析力优先），大片天空只需要**干净**（信噪比优先）。
如果整帧只给一个权重，就必须在"锐"和"干净"之间二选一。

DWT 的做法是：把画面分成"细节区"和"朦胧区"，用一张连续的 **R 场**（0…1）表示每个像素更偏哪一边，再让权重随 R 连续变化。

### 2.2 三个量

| 符号 | 含义 | 怎么测 |
|---|---|---|
| `C_i` | 第 i 帧的清晰度 | 全帧星点 FWHM 的中位数 → 归一化（越锐越大） |
| `S_i` | 第 i 帧的信噪比 | `中位噪声 / 该帧噪声`（噪声用高频差分估，避开背景梯度） |
| `T_i` | 吞吐量 | 该帧信号水平（可选，见 §2.4） |

三者都是**每帧一个标量**（瓦片扩展见 §9.3）。

### 2.3 融合公式

```
W(i, y, x) = C_i^(A·R) · S_i^(B·(1−R)) · T_i^fp        (1)
```

- `R = R(y,x)`：细节度。R=1 是细节区，R=0 是天空区。
- `A`：细节区愿意用多少信噪比换解析力（唯一需要标定的参数）。
- `B = 2`：**不是调出来的**。加权平均方差最小 ⇔ 权重 ∝ 1/σ²；而 `S = σ̄/σ_i`，所以 `S² ∝ 1/σ²`。
- `fp`：吞吐项指数。默认 **0**（原因见 §2.4）。

代码里对每一带求：

```python
W = strip_weights(C, S, R[y0:y1], A, B, T=T, fp=fp, beta=beta)
# 内部：W = exp(A·R·lnC + B·(1−R)·lnS + fp·lnT)
```

**逐像素归一 `mean_i(W) = 1`**：保证加权平均不改变总曝光量，成品背景亮度与等权叠加一致，权重的绝对值无意义、只有相对意义。

### 2.4 为什么默认关掉吞吐项（`fp = 0`）

HFG1-3 的 339 帧实测：

| 配置 | 天空 σ | 成品 FWHM |
|---|---|---|
| `fp = 2`（旧默认） | 1.4857e-05 | 3.34 px |
| `fp = 0`（现默认） | **1.4241e-05** | **3.31 px** |

原因：天空背景主导时，亮帧的散粒噪声同样高。`S²` 已经包含逆方差信息，再乘 `T²` 属**重复加权**——把少数亮帧抬得过高，有效帧数下降，噪声反而变大。

`fp=2` 只在帧间信号差异极大（例如透明度剧烈变化）时才有意义，所以留成可选项。

## 3. Drizzle：把像素变成"液滴"

### 3.1 基本模型

drizzle 不做插值。它把每个输入像素看成一个边长 `P` 的小方块（drop），按配准变换投到输出网格上，按重叠面积把能量分配出去。

```
输入像素 (i,j) ──变换──► 输出平面上的四边形 ──► 与各输出像元的重叠面积 → 权重
```

- `scale = s`：输出/输入像元比。`s=1` 不放大，`s=2` 放大两倍（更细的采样网格）。
- `pixfrac`：液滴边长相对像元的比例，`P = pixfrac · s`（普通黑白）。

`pixfrac < 1` 是 **drop shrink**：液滴比像元小，输出像元只被"部分覆盖"，相当于把信息集中到更小的区域——这是超分辨的来源，但要求亚像素抖动把空隙填满。

### 3.2 累积的量

对每个输出像素：

```
num = Σ_i Σ_drop  w · v          （加权值和）
den = Σ_i Σ_drop  w              （权重和）
out = num / den                  （加权平均）
cov = den / Σ_i w_i              （覆盖比例，用来判空洞与裁边）
```

`num` / `den` 用 **float32 原子加**在 GPU 上累加；`den` 同时充当覆盖率。

## 4. 结合点：权重乘进液滴，而不是叠完再乘

这是整个软件最关键的一步。

普通做法：先各自 drizzle 出单帧图，再按权重做像素级平均。缺点是每帧都要算一遍完整的输出画布，内存与带宽乘以帧数。

DWT-Drizzle 的做法：**把 `W(i,y,x)` 直接乘进第 i 帧在该像素的液滴贡献**：

```
num += W_i(x,y) · v · A_overlap
den += W_i(x,y)     · A_overlap
```

数学上等价于"逐像素加权平均"，但只遍历一遍、只保留一个画布：

```
out(x,y) = Σ_i W_i(x,y)·v_i(x,y) / Σ_i W_i(x,y)
```

好处：

1. 权重可以逐像素不同（这正是 DWT 需要的）；
2. 内存只与输出画布有关，与帧数无关；
3. 天然支持分带——每带独立累加，最后拼接。

### 4.1 分带与并行

全幅 6000×4000、几百帧时，`(n, H, W)` 权重场是不可能实体化的。实现按**行带**（默认 40 行）循环：

- 每带只物化 `(n, band, W)` 的权重；
- 每带独立做散射、累加、排异；
- GPU 上整块画布常驻显存，分带只影响 dispatch 次数。

### 4.2 GPU 端的注意点

- 用 `atomicAdd<f32>` 累加 `num/den`（需要 `shader-float32-atomic` 特性，本机与主流显卡均支持）；
- 原子加**没有固定顺序**，所以同一输入跑两次，逐像素会有 ~1e-5 量级的差异（实测 0.0007% 像素、最大 56% 的极少数像素）——这是浮点求和顺序，不是串扰；
- 后端失败会**明确回退并打日志**：`[wgpu][fallback] reason=…`，正常应为 `backend=canvas fallbacks=0`。

## 5. Bayer drizzle：彩色相机的特殊情况

### 5.1 问题在哪

拜耳传感器每个 2×2 方块只有一个 R、一个 B、两个 G。也就是说：

- **每个彩色平面在空间上只有 1/4 的采样点**，格点间距是 **2 个源像素**；
- R/B 的信噪比天生只有 G 的一半（同样的曝光时间）。

如果先 debayer 再 drizzle，插值会引入伪影和分辨率损失；PI 与 Siril 的共识是：**直接对未 debayer 的校准帧做 drizzle**（1× 档是官方推荐做法）。

### 5.2 掩膜：只允许同色样本落进来

对每个输入像素 `(x,y)`，按拜耳图案取颜色：

```
RGGB： color = (y%2, x%2) 的查表结果
```

散射时，输出像素只接受**同色**的样本；否则 R 会污染 G。

### 5.3 液滴尺寸必须按"格点间距"算，而不是"像元"

这是本项目踩过的最大坑。

- 同色格点间距 = 2 源像素；
- 2× 输出时，相邻同色样本在输出网格上相距 **4 个输出像素**；
- 若仍用 `P = pixfrac·s`（2 像素），液滴之间必然留缝 → 输出像素拿不到样本 → **2×2 黑网格**。

实测（M81 8 帧、2×）：

| pixfrac | 无样本像素比例 |
|---|---|
| 1.0 | 6.16% |
| 0.8 | 12.7% |

修正：

```
P = pixfrac · s · 2 · (1 + overlap)      （CFA 时；overlap 默认 1.15 于 2×、1.0 于 1×）
```

日志会写明：`[CFA] 液滴边长按同色格点铺满：pixfrac 0.8 → 1.0`。

### 5.4 2×2 去格点

即使铺满，四个相位拿到的样本数仍略有差异（相位增益 ~0.9%），强拉伸下表现为细密网格。

处理：写盘前用四个相位的中位数估计增益并归一到均值：

```
gain[p] = median(phase[p]) / mean(median(phase[*]))
out[p] /= gain[p] · (1/mean(gain))
```

实测把 M101 成品的相位差从 0.90% 压到 **0.064%**（约 14 倍），且只改常数、不加噪声。

### 5.5 两遍补相位（少帧时）

帧数少时，亚像素抖动不足以填满所有输出相位：

- 第一遍用**真实样本足迹**（`P = s`）→ 锐，但内部空洞可达 33%；
- 统计内部空洞比例，若 > 0.02%，只对空洞像素用 `2s` 液滴**重跑一遍**并合并。

日志：

```
[CFA] 两遍 drizzle：第一遍内部未覆盖 32.96% → 只在空洞处用 2× 液滴补一遍
[CFA] 两遍合并：补上 N 个像素（内部 M），其余保持第一遍锐度
```

实测：内部空洞 32.96% → **0**；总未覆盖 13.66% → 2.51%（全在边缘）；噪声仅 +1.6%。

### 5.6 合成 RGB

三个通道各自 drizzle 出单色图，再合成：

- 默认**不做通道平衡**（与 WBPP 的 ChannelCombination 一致）；
- 可选「加性」「乘性」两种平衡；乘性会把饱和星一起放大，产生彩色边，故默认关；
- 接近饱和的像素（≥0.985）取三通道均值 → 星点核心中性白。

## 6. 排异：在散射之前，还是之后？

### 6.1 顺序

```
每帧散射 ──► num/den 累加 ──► 得到该像素的 n 个样本 ──► 逐像素排异 ──► 重算平均
```

因为液滴散射是线性的，先累加再排异在数学上等价于"先排异再累加"，但只需保留少量样本，代价低得多。

### 6.2 两种排异

| 模式 | 尺度估计 | 特点 |
|---|---|---|
| winsorized | 块内中位数 | 快（1/9 抽样），卫星线穿过块时不至于把阈值拉松 |
| ESD（Rosner） | 逐像素 std / MAD | 更严，3 轮迭代，慢 |

`rej_k` 默认 3.5。实测：**开/关对天空噪声几乎无影响**（1.4857 vs 1.4875e-05），可以放心开着去卫星线。

### 6.3 两个边界情况

- **所有样本都被剔**：保留偏差最小的那个真实样本，绝不写 0（写 0 会变成"黑坑"）；
- **根本没有样本**：写 NaN，交给自动裁边，不用最近邻伪造。

## 7. 配准（简述）

drizzle 需要每帧的几何变换。实现顺序：

1. 星点检测（上限 240 颗，剔除贴边与最亮饱和星）；
2. 三角形匹配求相似变换（尺度先验 1±2%，拒绝 0.43 这类伪解）；
3. 全星验证（命中率与残差；稀疏场用"绝对命中 ≥20 且残差 ≤0.6×rad"）；
4. 漂移一致性：位移偏离帧间趋势 >3 px 的帧判错配；
5. 链式兜底 + 全局平差：直配失败的帧先与邻居配准再复合；直配与相邻观测一起做加权最小二乘，解 dx/dy/θ/ln(scale)。

## 8. 参数如何影响结果（速查）

| 参数 | 作用 | 建议 |
|---|---|---|
| `A`（清晰度） | 细节区权重幂 | 黑白 14~20；**彩机 ≤6**（A=10 时单帧逐像素可独占 409×，小星周围出黑坑） |
| `pixfrac` | 液滴大小 | 1.0 最稳；有充分抖动可试 0.7~0.8（彩机 CFA 会被自动抬到铺满） |
| `scale` | 输出采样 | 1× 最通用；抖动充分或想超分辨用 2× |
| `rej-k` | 排异强度 | 3.5；星空极干净可 4~5 |
| `flux_pow` | 吞吐权重 | **0**（默认）；透明度剧烈变化时才试 2 |
| `match_scale` | 按参考图标定亮度 | 要与 WBPP 直接对比时开 |

## 9. 已知限制与"试过但无效"的方案

### 9.1 PSF 空间均匀性

A 越大，好视宁区被推得越锐，全幅 PSF 分布越散：

| 配置 | p10 / p50 / p90 (px) | 离散度 |
|---|---|---|
| A=6 | 2.74 / 3.06 / 3.77 | 1.37× |
| A=0 | 3.31 / 3.43 / 3.89 | 1.18× |
| WBPP | 3.08 / 3.18 / 3.55 | 1.15× |

SXT 之类假设单一 PSF 的工具，对 1.37× 的离散更敏感，所以做去星前建议 A ≤ 6。

### 9.2 瓦片式清晰度权重（实验，默认关）

设想：每帧按 8×8 瓦片各测一个 FWHM，让每个区域自己挑最锐的帧。
实测无效：`spread 1.40×`（与全帧 1.37× 无统计差别）。

原因：**场依赖是所有帧共有的**（每帧都是中心锐、边缘软，来自光学与后截距）。按区挑帧只能补偿帧间不同的 patchy seeing，改不了共有场。

### 9.3 联合 CFA 重建（RL / 加权最小二乘）

试过两版，同噪声下只优 2~3%，而耗时 306 s vs 40 s，χ² 17~54 说明模型失配主导——判死。

### 9.4 其它

- `--crop` 与 `--frame` 同时使用时倍率换算仍有偏差；
- 1× 真 CFA 的 PSF 空间均匀性弱于 WBPP（原因见 9.1）；
- 未做代码签名，macOS 首次打开需 Gatekeeper 放行。

## 10. 小结：三个"为什么"

**为什么要把权重乘进液滴？**
因为 DWT 的权重是逐像素的（细节区/天空区不同），只有进到散射里才能在遍历一遍的前提下实现逐像素加权平均。

**为什么 CFA 的液滴要乘 2？**
彩色平面只有 1/4 的采样，同色格点间距是 2 源像素；液滴若不覆盖这个间距，输出必然出现 2×2 空洞——这就是黑网格的物理来源。

**为什么 A 和 flux_pow 要限得这么保守？**
两者都是"幂律放大器"。A 过大 → 单帧在逐像素上独占权重，退化成单帧 → 采样坑暴露；flux_pow 过大 → 与 S² 重复加权 → 有效帧数下降、噪声上升。实测数字见 §2.4 与 §9.1。

# DWT‑Drizzle 叠加算法优化历程报告

版本截止：v2.5　｜　数据基准：`G:\HFG1-3\calibrated` O 通道 305 帧 × 1200 s（Deneb 区）
报告口径：所有数字均为**实测**；未标注者为原生像素刻度（非 ×2 输出刻度）。

---

## 0. 一句话结论

这份数据上，**算法层面的画质优化已经到顶**：FWHM 从单帧 4.52 px 压到 3.37 px（改善 25.5%），
天空噪声降到 1/5.8，等效帧数 N_eff 247/305。剩下的差距来自**共模系统误差**（约 6 成天空方差）
和**光学本身的边缘像差**，不是叠加算法能再压掉的。真正有量级收益的是三件事：
**配准不再丢帧**（296→305）、**画布与参考网格一致**（不再事后裁切）、**速度快了 2.8 倍**（1562→562 s）。

## 2. 已并线（进入产品）的改动

### 2.1 逐帧背景梯度校正 `--bgdeg`（v1.2，默认 1）

- 做法：读帧时存 32×32 块中位，扣掉天空平移后拟合平面（或二阶面），在 `FrameSet.frame/strip`
  与 drizzle 的取数口减掉；模型**不含常数项**（在全采用块上零均值），所以不动 `sky0`、不改排异阈值口径。
- 实测（16 帧单变量）：成品背景平面峰谷 1.70e−4 → 1.59e−6（**107×**）；块中位残差不变；
  全量 246 帧时逐帧振幅中位 0.75σ、残差 0.16σ。
- 代价：排异率 0.411% → 0.439%（可忽略）。二阶面在这批数据上无额外收益。

### 2.2 吞吐（透射率）权重 `--flux_pow`（v1.4，默认 2）

- 做法：在拿到位移之后量每帧星点总流量 T（跨帧归一、中位 1），权重乘 `T^flux_pow`，
  对齐 PI 的 PSF Signal Weight。
- 实测：跨 11 夜 24 帧 T 只在 0.782~1.087（离散 **7.8%**）；60 帧 A/B 开关两版 FWHM 都是 2.78 px，
  细节 N_eff 10.17 vs 9.53。**本批数据几乎无差别**，混透明度/混曝光时才有意义。
- 保留原因：公式上是对的，代价为零。

### 2.3 默认清晰度指数 A：20 → 14（v1.5）

- 60 帧扫描：A=20/14/10 → 整体 N_eff 37.1/41.8/45.7，细节 N_eff 9.5/12.7/17.6，
  星点 FWHM 2.78/2.85/2.96 px。
- 取 14 是「星点只软 2.5%、细节等效帧数 +34%」的折中。**A 是唯一的强旋钮，但已接近饱和**。

### 2.4 配准健壮性（v2.0~v2.2）——本轮**最有价值的改动**

三个真 bug 依次修掉后，配准从 296/305 变成 **305/305**：

| 问题 | 现象 | 修法 |
|---|---|---|
| 参考帧选错 | 参考帧的 `_rot_hist` 不对称时，其余帧全测不出位移（参与 1/20） | 选参考帧前先拿 S 最高的 3 帧试 `_rot_hist`，测不动就换 |
| 三角配准兜底没机会跑 | 纯平移分支 `bad[i]=True; continue` 直接跳过 | 主循环结束后统一对 `bad` 帧跑 `trireg.solve`，`n_in≥15 && rms≤2.0` 收回 |
| 全星验证按本帧归一 | 参考帧星少时结构性误杀 | 命中率改按 `min(len(s_i), len(s_ref))` 归一 |

- 新增 `core/trireg.py`（三角形描述子配准），对**旋转/尺度/平移/镜像**都不变；
  内点 935 对、残差 1.25 px、覆盖 100%（drz3 → O master）。
- 修后全量：O **305/305**（救回 9 帧，尺度 1.0193、旋转 2.78°），H **282/282**（救回 3 帧）。

### 2.5 画布与参考网格 `--frame` / `--match` / `--crop-cover`（v1.6~v1.7）

- 根因：`plan_output` 产出的画布是「所有帧落点外接矩形」，尺寸永远不等于 master，
  四角还是薄覆盖楔形（neff P10 103.7 vs 中位 252）——强拉伸后就是黑边与斑驳。
- `--frame <master>`：把参考帧→master 的相似变换复合到每帧上，画布直接取 master 尺寸。
  **关键坑**：`matchref` 的 `k` 与 drizzle `_xy_rows` 的 `k` 互为倒数，第一版乘错导致成品被放大一倍
  （FWHM 3.9→6.0、星点命中 0/567）。改乘 `1/k` 后命中 70%。
- `--match <master>`：叠完再用三角配准把成品搬到 master 网格（`_match.xisf`）。
- `--crop-cover 0.9`：按`ncov`（每像素被多少帧真正覆盖）算最大内接矩形，另存 `_autocrop.xisf`。
- 实测：305 帧 `--frame` 成品 **4056×5004，与 master 完全一致**，零像素 0.000%，
  边缘 3 像素电平 = 中心的 99.86%。

### 2.6 速度：1562.8 s → 562.3 s（2.8×）

| 阶段 | 优化前 | 优化后 | 做法 |
|---|---|---|---|
| 配准 | 690.4 | **92.0** | 尺度候选缓存（`_SCALES`）+ 三角兜底快化（`max_pts` 48、KD 候选 `k=2`、参考描述子只建一次，单帧 4.9 s→0.07 s） |
| 叠加 | 674 | **260** | CuPy GPU 按带处理 + 分带宽度按显存预算自适应（48→212 行） |
| 其余 | ~198 | ~210 | — |
| **合计** | **1562.8** | **562.3** | |

- GPU 与 CPU 逐项一致（FWHM 3.37、N_eff 247.5、排异率相同），`test_gpu_band` 逐位差 7.75e−07。
- 教训：GPU 带太窄反而更慢（旋转 176° 时一条 48 行的带要读 480 行）。

### 2.7 可观测性与工具（v1.8~v2.4）

- **叠加评价页**：成品 FWHM / 边缘轴比 / 覆盖 / 权重集中度四项体检。
- **权重场页**：R 场（细节 vs 朦胧）与 N_eff 可视化，带色标与悬停读数。
- **运行监控窗**：阶段/进度/SNR 大字 + 被排除帧表（含原因与单帧 FWHM）+ 实时日志。
- **自动调参 `--tune`**：抽 16 帧跑 A×r_mode 六组，硬约束后给建议（实测六组只差 2.4%）。
- **SNR 口径**：最终定为「单帧天空噪声 → 成品天空噪声」的比值（挖掉星点 14 px 圆盘），
  同时报 `√N_eff` 作理论上限（实测 5.8× vs 理论 15.7×，差额来自 drizzle 重采样把噪声抹成空间相关）。

## 3. 实验过、但**未并线**的方向（附判据）

### 3.1 exp1 目标 PSF 权重 —— 小样本假象

- 做法：设叠后混合 FWHM 目标，用 `w_i = exp(−λσ_i²)` 反解 λ。
- 7 帧小样本：细节 N_eff 6.00→22.05，FWHM 只 +0.03，看起来"零代价"。
- **全幅 30 帧复核推翻**：同样 N_eff≈16，A=6 给 3.31 px，目标 PSF 法给 3.40 px —— 现成 A 旋钮更好。
- 附带教训：混合方差写成 `Σw²σ²/(Σw)²` 会被帧数稀释（40 帧算出 0.60 px），必须用 `Σwσ²/Σw`。

### 3.2 exp2 逐帧 PSF 一致化（RL 去卷积）—— 收益来自锐化

- FWHM 3.46→3.24（rl16），但独立星表复测反而宽 10%；
  受控星斑基准：RL 一致化 2.38 vs **纯锐化对照 2.35** vs 最锐单帧 2.79 vs Wiener 3.32。
- 结论：长曝光的相位已被大气与跟踪抹平，多帧"相位相加"不存在，去卷积等于锐化（那是 BXT 的活）。
  环带亮度 +2.9σ→+8.1σ、噪声 ×1.10~1.52，**不采纳**。

### 3.3 exp3 逐像素噪声权重 + 网格 LN —— 数据前提不成立

- 决定性诊断：噪声方差 **96.7% 是整帧共变**（`σ(i,j) ≈ a_j·b_i`），
  逐像素权重的解析上限只有 **1.0002×**（最好块 1.0034×）——数学上等价于标量权重。
- LN（块中位亮度归一）也无效：帧间亮度差只有 0.19~0.26%，反而把朦胧区/天空 σ 弄差 2.8%/4.7%。

### 3.4 exp4 多尺度显著性 R 场 —— 画布修正后"活了一半"

| 画布 | 环带 Z 中位 | 天空 Z 中位 | 比值 |
|---|---|---|---|
| 并集画布（40 帧） | 2.38 | 3.30 | **0.72×**（我最初的判死结论，作废） |
| 参考网格（40 帧） | 4.43 | 2.15 | 2.06× |
| 参考网格（305 帧） | 4.69 | 2.17 | **2.16×** |

但 ROC 仍不可用：阈值取天空 P95（误报 5%）只抓到 8.5% 的环带；取 P75（误报 25%）才 57.8%。
**作为逐像素权重不成立**；作为"检测/显示图"是有价值的。

### 3.5 其它已否决

| 方向 | 结果 |
|---|---|
| `r-floor` 全局抬升 R | 细节噪声只 −0.6%，星云过渡噪声 +25~44%，N_eff 37.1→13.7，**赔本** |
| 按夜分组叠加 | 低频残差 0.000991→0.00167（**+68%**），每夜帧少压不住各自的系统误差 |
| 帧级模板一致性加权 | 帧间 32 px 平滑后相关 **0.996**，没有可降权的坏帧，价值上限极低 |
| 径向畸变项 | 逐帧 d2 全在 ±0.002 内（空转），这批镜头无可测畸变 |
| `--crop` + 翻中天 | 40 帧只 7 帧配准成功（伪缺陷，已定位为参考帧选错，见 2.4） |

### 3.6 系统误差诊断（关键的天花板）

用两半栈 S/D 分解（`tools/sysdiag.py`，两半各 20 帧、同一参考网格）：

- 天空区（最暗 25% 的 96 px 块）共模方差占 **60.8%**（P10 15%、P90 87%）；
- 按半径分：中心 65.4% / 中环 55.7% / 外环 58.7% / 最外 66.6% ⇒ **不是渐晕，是全幅均匀低频场**；
- `--bgdeg 2` 无效（94.1%→94.1%）；自造平场反而更差（65.6%→82.1%，因为混入真实大尺度星云）。

⇒ 即使把共模误差完美压掉，上限也只有 **√(1/(1−0.61)) ≈ 1.6×**（≈多拍 2.6 倍帧数）。
**这是数据与标定的问题，不是叠加算法的问题。**

## 4. 为什么"看起来没什么提升"

1. **画质已经在噪声地板上**：25.5% 的 FWHM 改善、5.8× 的噪声降低都发生在第一梯队改动里；
   之后的每一项（权重、排异、畸变、R 场）单独贡献都 <5%，肉眼看不出来。
2. **剩下的差距是共模系统误差（~60% 天空方差）**，叠加算法按定义压不掉它——它来自平场、
   天空梯度估计、传感器非线性这些**逐帧相同**的东西。
3. **边缘的像质是光学决定的**：单帧边缘轴比就已经 0.775，叠完 0.810（每档都比单帧更圆），
   没有"配准把边缘拖坏"这回事。

## 5. 还能做什么（按性价比排序）

| 优先级 | 方向 | 预期 | 代价 |
|---|---|---|---|
| 1 | **提高物理标定质量**：更好的平场（天光平场/多夜合成平场）、逐夜透过率、暗电流 | 触到 1.6× 天花板 | 前期拍摄/校准，非代码 |
| 2 | **多拍帧数**：共模误差按 √N 下降最慢，但它是 60% 的部分 | 与 √N 同阶 | 观测时间 |
| 3 | 把 exp4 的多尺度显著性做成**独立检测图**（不改权重） | 让 2σ 暗弱结构可见 | 低（`tools/detect_map.py` 已有雏形） |
| 4 | 局部 PSF 一致化（按视场分区做小核去卷积） | 星点更圆，非暗弱信号 | 中，且收益接近 exp2 的结论（锐化） |
| 5 | 插值核 / pixfrac 自适应 / 畸变模型 | 收益在噪声以下 | 不建议 |

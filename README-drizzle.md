### 逐帧背景梯度校正（`--bgdeg`）

**要解决的**：叠加里"背景"只做了两件事——逐帧减一个**常数**天空中位、和跨帧排异。
常数减不掉梯度（光污染方向、月光一次面、夜内天空漂移），而梯度被排异当成"缓变信号"
放行（阈值里的 `m·R·(a−sky)` 对缓变面天然失效）。结果是两晚各带一个方向不同的坡、
叠起来永远不抵消，成品里留下低频云状残差，同时把帧间权重比较污染掉——天空亮的半边
看起来"信号强"，R 和排异都跟着偏。

**做法**（`core/bggrad.py`，约 220 行，纯 numpy）：

1. 读帧时顺手记 32×32 px 块中位网格（`block_medians`，块中位抗星点/宇宙线）；
2. 天空平移后逐帧拟合低阶面：`[1, y, x]`（deg2 再加 `y², xy, x²`），**迭代 3 轮
   3σ 裁剪**——星云、星团这些真信号在残差上是同号大离群，会被裁掉，于是拟合的是天空；
3. 常数项不取拟合截距，而是令模型在采用块上**零均值**：减掉它不移动公共天空电平，
   `sky0` 与排异阈值口径完全不变；
4. 模型在 `FrameSet.frame/strip` 与 `drizzle._FsProxy.strip` 两处取数口逐帧减掉，
   原生路径、drizzle 路径、并行条带的 memmap 路径全部覆盖，条带边界无缝
   （`model_strip` 按行广播，与整帧逐位一致）。

**为什么拟合在原生坐标**：加性梯度是焦平面上的量（视场内的一次面），与帧怎么平移旋转
无关。D1 那版 `_ln_normalize`（块中位**比**）之所以翻车，不是因为位置，而是因为它是
乘法归一化：星云在帧间位置漂移，块中位比吃进星云亮度，把弥散结构当增益抹平 → 平均出
一团亮雾。加性低阶面 + 离群裁剪没有这条通路。

**效果**（HFG1，取 16 帧 × 1024² 裁剪、drizzle ×2，`--bgdeg 0` vs `1`，同参数）：

| 指标 | bgdeg 0 | bgdeg 1 |
| --- | --- | --- |
| 成品背景拟合平面的峰谷 | 1.70e−4 | 1.59e−6（**平了 107×**） |
| 块中位残差 RMS（背景结构是否被削） | 8.74e−6 | 8.95e−6（不变） |
| 全幅中位（天空电平） | 6.0057e−3 | 6.0074e−3（+0.03%） |
| 最亮 0.1% 像素（星核/亮星云）差 | — | 0.37% |
| 成品星点 FWHM | 2.84 px | 2.83 px |

日志里会多一行：

```
[背景] 逐帧梯度（平面，32px 块中位，裁剪 3σ×3）：16/16 帧拟合成功
       幅度中位 0.42σ  最大 0.53σ（0 帧 >2σ）  残差中位 0.06σ  用块 96%
```

**副作用**（请读）：低阶面分不清"光学梯度"和"同阶的平滑真实背景"，所以它会一并减掉
大尺度弥散星云的一次/二次结构——**在意大尺度光度时设 `--bgdeg 0`**。星点、纤维、团块
不受影响（块中位 + 3σ 裁剪把它们当离群）。`--bgdeg 2` 只在视场大、两侧渐变不对称时
才需要；平面拟合不掉的情况通常是渐晕（径向、非多项式），那是平场该管的事。

### 径向畸变项（自动，无需开关）

**要解决的**：纯相似变换（θ、尺度 k、平移 u）对**跨夜/转动过中天**的帧不够用——
同一颗星在画幅中心和边缘的残差不一样大。加一个一阶径向项 ρ' = ρ·(1 + d2·ρ²)
（以画幅中心为原点、rc = 0.5·min(h,w) 归一），每帧单独解 d2：

1. 先用已有的相似变换把星对配好；
2. 再用「相似 + 径向」联合拟合，d2 走 −0.08~+0.08 的网格、每次内层重解相似变换；
3. 残差改善超过 **15%** 才采纳，否则 d2 保持 0（这条阈值是防过拟合：百来颗星
   解 4 个参数已经勉强，再加一个必须有明显证据才动）。

采纳时日志会多一行：

```
  [位移] 第 37 帧径向畸变 d2=-0.0042（残差 0.61 → 0.33px）
```

d2 同时进入了 drizzle 的坐标映射（`_xy_rows` 的像元位置先做径向拉伸再做旋转/缩放），
不只是"拟合时好看"。

**在这批数据上它是空转的**：H 组 267 帧、O 组 289 帧逐帧解出来的 d2 全部落在
±0.002 以内（即 0），边缘星点轴比 0.798 → 0.800，FWHM 2.79 → 2.79 px。也就是说
这套镜头在 2752×2160 上基本没有可测的径向畸变，**边缘那点软化不是畸变造成的**
（单帧本身边缘 0.878、中心 0.921；叠出来的 0.76 主要是逐帧星点定位在暗弱边缘的
噪声、以及各夜 PSF 形状的差异）。留着这项是因为换成大视场、带减焦镜或 APS-C
画幅的数据时它就会开始起作用，而它不采纳时对结果没有任何副作用。

自检见 `tests/test_dist.py`：真值 d2=+0.010 时解得 −0.008（符号相反是对的——模型
是"帧→参考"的逆），残差从 1.48 px 降到 0.28 px；零畸变时解得 0.000，不会凭空
造出畸变。

### 输入已对齐（`--aligned`，v2.6.5 新增）

素材是 WBPP 的 `registered\` 帧时打开：`collect_frames(allow_aligned=True)` 放行这类路径，
`_run_group` 里强制 `drz_on = False`，跳过 `measure_shifts` 与 `drizzle`，走 `stack_strips`
（整数网格、零插值），权重仍是 `exp(A·R·lnC + 2(1−R)·lnS + fp·lnT)`。

实测（339 帧 O，A=20）：drizzle 2× 2.72 / drizzle 1× 2.66 / aligned 2.47 / 原版 DWT 2.32；
朦胧区 N_eff 264→278（不掉）。差额来自“进 drizzle 前那次双线性重采样”。

### 自动裁切到 master（`--match`）

`core/matchref.py`（新增）。给一张参考图，叠完把成品重采样到它的网格上另存，
不改变原成品：

```bat
main.py --cli --photos ... --out ... --match "G:\HFG1-2\master\masterLight_..._autocrop.xisf"
```

实现要点：

- 星点用最大滤波 + 亮度过阈（不需要 photutils），两图都按亮度排序，取前 150 颗做「两两位移投票」
  求平移；同时用 FFT 相位相关给一个候选，两条各解一次匹配，取匹配星多的那条；
- 平移对不上（例如参考与成品视场旋转差几度）时，按 0.25° 步长扫 ±4°，每次重投票 + 重匹配；
- 匹配后 `fit_rigid` 解刚体（旋转 + 平移，**无缩放**），再迭代一次最近邻；
- 像素尺度不靠画幅大小猜（成品画布常比 master 大一圈），而是把 1× 与 2× 两种假设各解一遍，
  取「匹配星数多、残差小」的那个；
- 重采样用 `ndimage.affine_transform(order=3)` 一次完成，头信息照抄参考（含 WCS）；
- 覆盖 < 30% 或残差 > 3px 时判定不可信，只写日志、不写文件，绝不覆盖已有成品。

实测：H 组 267 帧成品（4950×6459）对齐到 WBPP 的 H master（4056×5004），
匹配 1256 对、残差 0.596px、覆盖 100%，θ=-0.0002°。
自检 `tests/test_match.py`：造一张参考图再按已知 1.5° 旋转 + 平移 + 2 倍像素造成品，
解回 k=2、θ=+1.48°、残差 0.41px、覆盖 99.2%，重采样后星点偏差中位 0.00px。

### 自动裁边（`--crop-cover`，v1.6 新增）

drizzle 输出的是「所有帧落点的并集」，视场旋转或抖动大的时候，四角会留下没有被任何帧盖到
的空白楔形，边缘还会有一圈只被几帧盖到的薄带。这两处不是电平问题（天空中位在带子里也一样），
而是**样本数不够 → 噪声大**，一拉伸就成了黑边和斑驳。

于是新增按覆盖率裁边，叠完自动另存一份裁好的：

```bat
main.py --cli --photos ... --out ... --crop-cover 0.9
```

- 覆盖率从 `_drizzle_band` 里的逐帧落点面积数出来（`ncov`：该输出像素被几帧盖到），
  另存成 `<成品>_ncov.npy`；
- 阈值 `mask = ncov >= max(3, frac*max(ncov))`，先做 9×9 闭运算填掉针孔，再求**最大内接矩形**；
- 结果另存 `<成品>_autocrop.xisf`（连同 `_autocrop_neff.npy`、`_autocrop_R.npy`），原成品不动；
- 找不到能裁的矩形（或小于 32px）就只写日志、保留原画幅。

实测 20 帧 H：原画幅 5807×4991 → 裁后 4982×4057（69.7%），裁后边缘 3px 带的中位电平
0.0044082 与中心 0.0044157 一致、零像素 0.00%。

两个坑，写在这里免得再踩：

- **不能用 N_eff 当覆盖率**。N_eff=(Σw)²/Σw² 在星云区（R≈1、权重集中）只有 20 上下，
  按 0.9×max 阈值化会把整片细节区判成"没覆盖"；
- 求内接矩形前的闭运算必须 `border_value=1`，否则贴着画幅边的 4 个像素会被当成外面啃掉，
  全满的图也会被裁掉一圈。

### 三角形配准（`core/trireg.py`）

星点两两投票只解平移；遇到翻中天（约 180°）或两批数据像素尺度差 2%，就会判成“配不上”。
现在先走三角形配准：取最亮 90 颗星，每三点组成三角形，用「按边长排序后的两条比值」当描述子
（对旋转、尺度、平移都不变），匹配上三角形后用 Umeyama 一次解出「尺度 + 旋转 + 平移」，
再用全部星点算内点。判据是内点数和残差，**不看图像相关**——实测单帧图相关不可靠
（明知能配上的帧，相关也只有 0.01）。

日志形如：

```
[三角] 内点 935 对  尺度 1.0004  旋转 176.50°  残差 1.25px
[裁切] 三角配准：内点 935 对  尺度 1.0004  旋转 176.50°  残差 1.25px  覆盖 100.0%
```

内点 < 40 或残差 > 2px 时不采用，自动退回原来的投票/图像相关流程。

### 权重场查看（`maps_page.py`，v1.8 新增）

GUI 第三个标签页，把成品旁边的 `_R.npy`（分区权重场 R∈[0,1]）与 `_neff.npy`（等效帧数
`N_eff=(ΣW)²/ΣW²`）画成两幅彩色图，含色标条、分位数统计与鼠标悬停取数；N_eff 可选对数色标。

### 自动调参（`--tune`，v2.4 新增）

`core/tune.py`。叠加前从素材里均匀抽 N 帧（默认 16），裁中心 1200×1200，
把 `A ∈ {10,14,20} × r_mode ∈ {max,band}` 六组各跑一遍完整流程（子进程，复用 `main.py --cli`），

- 硬约束：FWHM 改善 > 0；N_eff ≥ 0.70 × 最高者
- 排序：FWHM 改善最大

给出建议，并在日志里打 `[调参] TUNE-BEST {json}`，GUI 收到这行会把 A / R 场定义填回界面。
明细写 `输出目录/tune_report.csv`。抽样只在临时目录做硬链接，不动原始素材；
跑完自动删临时目录。自检 `tests/test_tune.py`（抽样均匀性、日志解析、硬约束）。

### SNR 指标口径（v2.4 修正）

`[SNR] 单帧天空噪声 → 成品 噪声降低 x×（= 等效 SNR 提升）`。

口径：两张图先归到同一像素尺度（成品若被 drizzle 放大过，按尺寸比合回原像素），
再各自算「每像素天空噪声」——中值滤波（5px）扣掉星点与大尺度结构后，取 32×32 块内
`1.4826 × MAD` 的中位；**挖掉星点周围 14px 的圆盘**，否则叠好的图星点更锐、边缘更陡，
星芒会被误当成噪声。

为什么不用「逐星信噪比」：那需要先在两张图上找到同一批星，还要保证星点周围没有结构污染，
换一批数据就会给出 0.7× 或 12× 这种明显失真的值（都实测过）。噪声比只依赖两个标量，
可重复、可比，而且这正是叠加真正带来的东西：信号不变、噪声下降。

日志里同时给 `√N_eff`，实测通常落在理论的 30%~80%（drizzle 重采样会把噪声抹成空间相关，
插值核越大、pixfrac 越小，这个比例越低）。看「噪声降低」和「√N_eff」两条一起判断更稳：
两者差得离谱说明帧间电平/天空没对齐，而不是叠加失败。

### 排异阈值分块（v2.5）

排异的 MAD 以前是整条带一个标量：星云区会被结构抬高、天空区又被压得过紧，
结果是要么啃掉星云细节、要么放过拖线。现在按 64×64 输出像素分块估 MAD，
阈值跟着局部噪声走（`core/drizzle.py` 的 `REJ_BLOCK`、`gpu_band.py` 同口径）。

实测（O 40 帧、全幅）：分块与整幅的剔除率都是 0.399%，FWHM 都是 3.04px
—— **这批数据上两者等价**，因为各块噪声本来就均匀。留着它是因为它对
"半边亮星云、半边深空"这类构图更稳，代价可以忽略。

### 径向背景 `--bg-r`（v2.5）

`--bgdeg` 的一阶/二阶面吃不掉"径向"的渐晕与平场残差，所以加了偶次项拟合
`r²`/`r⁴`（`--bg-r 2` / `--bg-r 4`，默认 0 关）。径向是旋转不变量，跨夜翻转也适用。

实测（O 通道三帧，块中位残差）：平面项之后残差 0.40~0.51σ，其中 `r²` 系数只有
0.001~0.03σ、`r⁴` 0.2~0.86σ 但一正一负互相抵消 —— 40 帧成品上边缘/中心低频
残差比 **1.40 → 1.39**，等于没有效果。原因是这批数据用 WBPP 的平场做过校正，
帧级径向残差本来就被压掉了。所以默认关，只在"没用平场/平场不匹配"的素材上开。

图形界面就是 `gui.py`（本包自带，双击 `启动-图形界面.bat` 打开），不依赖作者的 `wevvmold`。

### 叠加评价页（`eval_page.py`）

界面第二个标签页。把成品的 `.xisf` 拖进去，它自动补上同目录的 `_R.npy` / `_neff.npy` / `_weights.txt`，点「开始评价」，几秒出四块读数：

1. 画幅 / 有效覆盖 / 天空 / 背景 σ
2. 星点：数量、FWHM 中位与 P10、P90，以及 5 个半径环带的 FWHM 与轴比 b/a（图形化两条曲线）
3. 权重：N_eff 中位/P10/P90、空像素占比、R 场均值与细节区 N_eff
4. 帧权重：单帧 FWHM 范围、C/S 范围、最锐/最糊帧号

判据写成结论直接显示：边缘 FWHM 比中心差 >12% 指向配准；边缘轴比 <0.85 指向配准残差随半径；N_eff 的 P10 过低指向覆盖不均；C_max >2.5 指向细节区被少数帧主宰。

实现上不依赖 matplotlib：星点用 `maximum_filter` 取峰 + 7×7 二阶矩（`FWHM = 2.3548σ`），曲线是用 `tk.Canvas` 手画的。整个评价在一个后台线程里跑，主界面不卡。

GUI 另外加了一个 **存为默认** 按钮：把当前整套参数写进 `%APPDATA%\DWT_Drizzle\settings.json`（软件在开始叠加和关闭窗口时也会自动存）。通道勾选也会一起存——下次扫描完通道列表会按上次的勾选恢复。

如果你要把这套改动搬到自己的源码树里重新打包，同样只需要 `core\` 下的三个文件（`drizzle.py`、`pws.py`、`pws_params.py`），原版 GUI 会自动多出"启用 drizzle / 输出倍率 / pixfrac / 裁剪"四个控件，界面代码一行都不用改——参数是在 `PARAMS` 表里声明的。

### 输出网格参考（`--frame`，v1.7 新增）

原来的画布是「所有帧落点的外接矩形」，尺寸取决于位移范围和旋转，永远不会正好
等于 master，所以想和 master 对比只能事后裁切或重采样——裁切会丢画幅，重采样
多一次插值。

`--frame <参考图.xisf>` 把这件事挪到叠加阶段：先在 seed 帧和参考图之间解一次
相似变换（同一个三角形求解器），把它**复合到每一帧的变换上**，画布直接取参考图
的宽高、缩放 1、无平移。于是成品从第一张像素起就是 master 网格：

```
[网格] 星点对账 1068 对，整体扣掉 (-0.21, -0.03)px
[网格] 输出画布直接取参考 masterLight_..._autocrop.xisf 5004×4056（放大 1.9993× 旋转 -0.01°）
```

要点：
- `--frame` 管**画布**，`--match` 管**事后重采样**；两个给同一张 master 时，
  用 `--frame` 就够，`--match` 可以不给（少一次插值）。
- 复合时 k 的语义要取倒数：`matchref` 的 `k` 是「源/参考像素」，drizzle 的 `k`
  是「帧→画布放大倍数」，直接相乘会把成品放大一倍（FWHM 从 3.0 变 6.0）。
- 最后一步用 seed 的星点和 master 对一次中位偏移（约 0.2px 量级）再整体扣掉，
  所以和 master 的星点中位偏移是 0.00px。
- 参考图比素材小（master 通常是 autocrop 过的）时，画布外的帧像素直接落在框外，
  不会在画面里留黑边。

## 一、结论先说

| 问题 | 结论 |
| --- | --- |
| 加得进去吗 | 加进去了，而且是唯一正确的位置：**第 ④ 步"一次加权平均"**被换成 W 加权的 drizzle 累积 |
| 统计层动了吗 | **一行没动**。① 归一化、② R 场、③ 权重公式、A=20 / B=2 的标定全部照旧 |
| 采样率提高了吗 | **这套素材（σ_psf≈1.6–1.7 px）几乎没有提高**，原因见第五节——数据本来就不欠采样 |
| 那它有什么用 | ① 能吃**未对齐**的原始子帧（原生路径对这种输入会直接糊 −65%）；② 输出网格更细且**重采样不加宽**；③ 为后续反卷积/展示留出余量 |

一句话：**drizzle 解决的是"几何"问题，PWS 解决的是"统计"问题，两者正交。** 你的软件原来要求输入已对齐，这一步只能靠外部软件做（多半还带插值损失）；现在这一步被并进了叠加器内部。

### 1. `core/drizzle.py`（新增，约 800 行）

只依赖 numpy + scipy，不引入新依赖。对外 API：

```python
measure_shifts(fs, stars, ref=0, half=8, log=None)
    -> {'dx','dy','theta','scatter','keep','n_keep','n_bad','n_fill','n_rot',
        'dx_range','dy_range','theta_range'}

              pixfrac, band_h, rot=None, theta=None, native_shape=None,
              log/emit/cancel=...)
    -> {'stack','neff','coverage','rej_rate','wmax'}
stack_sharp_reference(fs, idx, dx, dy, plan, pixfrac, band_h=128, rot=None, theta=None)
plan_output(shape, dx, dy, scale, margin=1.0, theta=None) -> {'s','ox','oy','W','H'}
```

**逐帧刚体配准（不只是平移）**——2026-11-10 晚上补的，起因是 232 帧 O 通道整晚叠加
"完全不对"：星点没对齐、过中天的帧没翻转、亮星出现怪光环和中心黑点。

- 那台设备的帧场（`SITELAT=39.2667`、`PIERSIDE=West`、`CENTAZ` 整晚从 30° 扫到 346°）
  会**连续转 3~5°**，过中天再加 **180°** 翻转。只用平移（或只判 0/180°）时，转过 3° 的
  帧会把星点搬到别人的星上，逐像素中位数再把这些错位的亮核当离群值剔掉——表现就是
  "没对齐 + 鬼影 + 中心黑点"。
- 现在每帧解 `q ≈ R(θ)·p + u`：星点对长度谱配对（只比长度不比位置，能吃掉任意旋转）→
  角度直方图出粗角 → 匹配评分 → SVD 精修 → 全分辨率重心精修。日志会打印
  `相对参考帧旋转 -177.6°~+0.07°（中位 …），其中 122 帧接近 180°（过中天翻转）`。
- 落点改成精确的旋转+平移散点（`_scatter_band`，按输出像素做盒式面积重叠），不再是
  可分离的两条稀疏矩阵；只有全部帧 |θ|≈0 时才走原来的快速路径，行为与之前完全一致。

**像元尺度不一致（换了光路/减焦镜）**——同一晚会混进尺度差 2% 的帧（2026-11-01 那批
`k=1.020`）。长度谱对不上就没有角度峰，这些帧会静默退回"只平移、θ=0"，混进叠加后
就是整片螺旋状鬼影。现在模型是相似变换 `q ≈ k·R(θ)·p + u`：

- 先按 `k ∈ [0.94,1.06]` 扫星表（只缩放**坐标**，不重采样图像，几十毫秒），找得到角度峰
  的那个 k 作为初值，再做完整的最小二乘（SVD 的 Umeyama 解）。
- 日志会打印 `[位移] 第 N 帧像元尺度 1.020（换了光路？），按此尺度配准` 和
  `[位移] 像元尺度 1.000~1.019（中位 1.000）`；尺度只在对齐点 ≥20 对时才采纳，
  否则退回 θ+u（避免少数点把 k 拟飞）。
- 落点边长按 `pixfrac·s·k` 逐帧算，所以不同尺度的帧合起来不会互相糊掉。

**星点检测的半步修正**——检测器在 2× 分箱图上工作，第 i 块的中心是 `(i+0.5)·2−0.5`。
早先漏了这半步，检测点相对质心恒偏 −0.5 px；平移模型里这个偏差两边都有、会抵消，
但一转到 180° 就反号，变成 **正交帧之间 1 px 的系统错位**（正好是"双星 + 黑心"的成因）。
修正后 θ≈180° 的帧逐块残余从 ~1.3 px 降到 ~0.5 px。


1. **拟合必须带截距**。数据里公共天空是 ~1e3 量级，不带截距时那一截会被强行摊进斜率——

   一开始误写成"某个子块的天空中位不变"——梯度面本来就逐点变化，子块天空被修正正是目的，
   被冻结的是全幅天空电平（排异阈值以它为零点）。

## 三、怎么用

**GUI**：高级面板里多了三项，勾选"drizzle"即可；命令行参数由 `PARAMS` 自动生成。

```bash
python main.py --cli --photos G:/HFG1/HFG1/DATE_2026-11-01/LIGHT \
               --out  G:/HFG1/drz --tag drz \
               --drizzle --drizzle-scale 2 --drizzle-pix 1.0
```

- `--drizzle-scale 2`：输出边长翻倍（像素数 ×4）。σ_out = s·√(σ_nat² + p²/12)，目标落在 1.5–2 px。
- `--drizzle-pix 1.0`：默认值，**任何数据都能铺满画布**；只有确认有真实亚像素抖动时才建议 0.7–0.8（锐 ~1–1.5%，但边缘会出现未覆盖像素）。
- 其余参数（A、rej_k、env_*、n_star……）语义完全不变。

日志里会多出几行：

```
[drizzle] 帧间位移 dx -28.22~+45.16px  dy -59.99~+108.20px  逐星残差 0.510px  4.3s
[位移] 14 帧自身星点对不上，已用前后可靠帧插值补位移
[drizzle] 注意：各帧位移的亚像素相位几乎全同 ⇒ 输入已被对齐/插值过。此时 drizzle 只做一次无损失的重采样，采样率不会提高
```

最后那条警告是关键：**如果你的输入是别的软件对齐过的**（DWT 原来的使用方式），相位已经被插值抹平，drizzle 拿不到采样增益——它只会把画面无损地搬到更细的网格上。

### 借 WBPP 的 .xdrz：省掉自己测星点

PixInsight 的配准默认会插值（Lanczos-3）把帧重采样到同一网格，但它的 **drizzle 并不用那些插值后的图**：StarAlignment 在勾选 *Generate drizzle data* 时，会把每帧的几何变换写进 `.xdrz`，drizzle 阶段再拿**原始标定帧的像素**按这个变换重新投影。所以 `.xdrz` 里存的就是「帧 → 参考网格」的纯几何，正好可以喂给本项目的 drizzle 核：

```bash
python main.py --cli --photos "G:/HFG1-2/calibrated/Light_..._FILTER-O_..." \
               --out G:/HFG1/drz_o7 --tag o7 \
               --drizzle --drizzle-scale 2 \
               --xdrz "G:/HFG1-2/registered"
```

- `--xdrz` 指向 WBPP 的 `registered\` 目录（里面是 `*_r.xdrz`），程序按**源文件名**（`.xdrz` 里的 `<SourceImage>`，也就是 `calibrated\` 里的那帧）和素材配对；对不上的帧会被排除并在日志里列出。
- 读的是 `<AlignmentMatrix>`。实测约定：矩阵按 (x, y) 行优先存储、方向是**参考坐标 → 源坐标**（和直觉相反），程序内部取逆后分解成 (k, θ, u) 再走与自测路径完全相同的 splat，所以两种模式可以互换比较。
- 精度：两帧相对几何的独立校验为 92.5 % 星点在 3 px 内匹配、残差中位 (0.13, −0.16) px、rms 0.26 px（与自测的星点质心噪声同量级）。
- **不要**同时把 PI 的 `<ScaleFactors>`/`<Weights>` 也乘进去：曝光归一由 `prepare_frames` 负责，权重必须是 PWS 自己的 W（否则式 7 与 B=2 的推导都失效）。
- 日志里会写 `[drizzle] 几何来自 WBPP .xdrz：…`，并对每帧打印旋转与像元尺度范围。

留空 `--xdrz` 就回到自测模式（`measure_shifts`），两条路径得到的几何应当一致，可以用同一批帧互相对照。

### 素材从哪来：三场校准与自动分组

drizzle 吃的是「**已校准、未对齐**」的原始子帧。按这个标准挑目录：

| 素材 | 能用吗 | 原因 |
| --- | --- | --- |
| 相机直出的 `LIGHT` | ✗ | 没做 bias/dark/flat。平场暗角、坏点会被 R 场当成"结构"，排异也会误删 |
| WBPP 等流程的 `calibrated\` | ✓ **首选** | 已做三场校准，且是纯裁剪，没有重采样 |
| WBPP 的 `registered\` | ✗ | 已用 Lanczos-3 插值对齐，亚像素相位被抹平，drizzle 只会再做一次重采样 |

实测核对（`G:\HFG1-2\calibrated` 对比 `G:\HFG1\HFG1\DATE_2026-11-01\LIGHT`）：校准帧 = 原始帧裁掉左 50 px、右 270 px、下 80 px 的 overscan 区，FFT 相位相关残差 **0.000 px**、相关系数 0.898 —— 除裁剪与线性缩放外没有动过任何像素，抖动完整保留。

分通道、分曝光都不必手工做：

- **通道**：读 `FILTER` 头（FITS / XISF 都读），按 H/O/B/G/R 自动分组。
- **曝光**：同通道不同曝光默认进同一组；每帧先按 `300/exptime` 归一到同一量纲再测 σ、算权重，成品最后按组内曝光中位回乘（日志会出现 `[量纲] 成品回乘 ×3（曝光中位 900s / 归一基准 300s）`）。
- **非 Light 帧**：读 `IMAGETYP`，Flat/Dark/Bias 自动跳过（`[分组] 跳过 155 张非 Light 帧（Flat / Dark / Bias）`）。
- **已对齐帧**：路径中含 `registered` / `aligned` 的自动跳过（`[分组] 跳过 N 张 registered/ 下的帧…`）。

实测：`--photos G:/HFG1-2/calibrated` 一次扫到 649 个文件，跳过 155 张 flat，自动分成 H×218 / O×232 / B×12 / G×12 / R×20 五组；5 组各试跑 4 帧共 45.9 s。

### 默认 A：20 → 14（v1.5）

A 是唯一需要标定的旋钮，也是唯一"风格"开关。60 帧 H 实测（同一块掩膜量高频噪声）：

| A | 整体 N_eff | 细节区 N_eff | 细节区高频 σ | 星点 FWHM |
|---|---|---|---|---|
| 20 | 37.1 | 9.5 | 1.038e−2 | 2.78 px |
| **14（新默认）** | 41.8 | 12.7 | 9.92e−3（−4.5%） | 2.85 px（+2.5%） |
| 10 | 45.7 | 17.6 | 9.20e−3（−11%） | 2.96 px（+6.5%） |

A=20 时细节区一个像素实际只由十来帧决定（N_eff 9.5/60），权重过于集中，这也是"PSF 信号权重
看起来偏低、画面比 WBPP 毛"的根源之一。14 把有效帧抬到 12.7、噪声降 4.5%，代价只是星点软
2.5%；想要最锐的星点仍可手动填 20，想要最干净填 10。

（另测过 `--r-floor 0.2/0.35` 把 PSF 权重铺到星云区：细节噪声只降 0.6%，星云过渡区噪声反而
涨 25~44%、整体 N_eff 掉到 13.7 —— 赔本，不建议用。）

### 吞吐权重（`--flux-pow`，v1.4 新增）

原来的权重只有两项：清晰度 `C_i`（这帧锐不锐）和噪声 `S_i`（这帧干净不干净）。
两者都不回答"这帧到底收了多少光"——通透的夜晚信号高、薄云的夜晚信号低，而两者的
噪声可能差不多。PI 的 PSF Signal Weight 正是以收光量为核心，所以我们在那个口径上
一直吃亏。

现在多了一项 `T_i`：配准之后，把星表按每帧自己的 (θ, k, dx, dy) 投回去，在**同一批
星**上量 7px 孔径、环带平面扣背景的流量；逐星按"该星跨帧中位"归一（饱和、邻居污染、
孔径吃光度这些静态偏差就消掉了），再取每帧中位并整体归一。权重变成

    W = C^(A·R) · S^(2(1−R)) · T^flux_pow

- `--flux-pow 0` 关闭；默认 `2.0`（与逆方差同量级，和 PI 的口径接近）。
- 实测（HFG1，H 通道）：跨 11 个夜晚抽 24 帧，T 只有 0.78~1.09、相对离散 7.8%；
  60 帧 A/B 里 FWHM 都是 2.78px，细节区 N_eff 10.17 → 9.53、σ 1.508e-3 → 1.547e-3。
  **也就是说这批数据本身吞吐很稳，开与不开差别很小**——真正有用的场合是通宵混着
  薄云/低空/不同天顶距的素材。
- 早期版本把流量测在配准**之前**（星表坐标是参考帧的像素，指向不同的帧会落到别的
  天区上），T 会散到 0.09~30，把权重放大几万倍；现在测在配准之后，这个坑已经封住。

### 关于拟合告警（`fit(s) may not have converged`）

photutils 逐颗星做高斯 PSF 拟合时，被邻星挤压、贴边、饱和或宇宙线打中的星会有个别不收敛，
`astropy` 在协方差奇异时还会抛 `divide by zero` 的 RuntimeWarning。这些星本来就会被剔出中位数，
**不影响 C_i**，但一帧 120 颗、几百帧就是上万行输出。

现在的做法：拟合期间静音 `photutils` 日志与 `RuntimeWarning`，只计数，每组结束汇总一行：

```
[星点] PSF 拟合 3600 颗次，其中 41 颗未收敛/协方差奇异（1.1%，已剔除，不影响中位数）
```

正常 0~5%；持续 20% 以上说明星表本身选得不好（调 `--n-star`，或避开拥挤星场裁一块再试）。

## 四、数学：为什么能无缝接进去

原生第 ④ 步（文章 Eq12）：

```
S_r = Σ_i W̃_{i,r} · D_{i,r} / Σ_i W̃_{i,r}     （W̃ 已按 mean_i W = 1 归一）
```

drizzle 版：

```
S_r = Σ_i W_{i,r} · ( Σ_p a_{i,p→r} · D_{i,p} )  /  Σ_i W_{i,r} · c_{i,r}
c_{i,r} = Σ_p a_{i,p→r}    （该帧每个输入像素贡献到该输出像素的覆盖份额之和）
```

- `a` 只含**几何**（平移 + pixfrac 的落点面积），`W` 只含**统计**（清晰度/信噪比）。不把 a 折进 W，Eq7 与 B=2 的最优性推导才依然成立。
- 分母 `Σ W·c` 自动吸收覆盖率与 pixfrac，原生的 `mean_i(W)=1` 归一化因此在 drizzle 分支里是多余的（保留也不影响比值）。
- 单帧单像素的特例 `a = δ`、`c = 1` 时，上式**逐位退化为 Eq12**（自测里最大差 1.97e-05，即 float32 舍入）。
- 权重仍是 `W = C^(A·R) · S^(B(1−R))`；R 场、C、S 都在**输出网格**上重建，所以 `σ_psf → s·σ_psf`、星窗 `33/29` → `33s/29s`、拖线核 `h → s·h`。
- 排异（Eq11）在输出网格上做：`anchor = 逐像素中位数`、`mad = 1.4826·MAD`、`thr = κ·mad + m·R·max(anchor−sky,0)`，`m` 仍取 R>0.5 像元上 `|D−a|/(a−b0)` 的 P99，门槛仍是 `1/3`。
- 有效帧数 `N_eff = (ΣW)²/ΣW²`（按帧权重，与原生等价）。

位移测量是两段式：4× 分箱 FFT 相位相关给粗位移 → 在粗位移处开窗做**迭代**亚像素重心（最多 6 次，收敛到 0.02 px）→ 多颗星取鲁棒中位。个别帧星点对不上时，用前后可靠帧线性插值补位移（望远镜漂移是连续的），并用该帧自己的粗位移做 ±25 px 校验。

## 五、实测（HFG1，60×H + 53×O，1200 s）

原始子帧：`G:/HFG1/HFG1/DATE_2026-11-01/LIGHT`，H/O 混放，按 FILTER 分组，**未对齐**（帧间漂移 10–100 px）。

| 波段 | 帧数 | 输出 | 叠加耗时 | 排异率 | 成品 FWHM | 单帧中位 | N_eff 中位 | σ_psf |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| H | 60 | 6295×4821 | 133.8 s | 1.998% | 3.34 px | 3.81 px | 28.35/60 | 1.62 → 3.24 |
| O | 53 | 6358×4774 | 178.5 s | 1.465% | 2.98 px | 4.10 px | 42.12/53 | 1.74 → 3.48 |

- 未覆盖（纯 0）像素 0.265%，全在画布边缘（平移后的外框）。
- 位移补帧：H 补 14 帧、O 补 9 帧，其余帧自身测得出。
- 亮星径向剖面单调、无负环（图上"黑圈"是显示拉伸的错觉，不是数据）。
- **对照组**：同样的数据走原生路径（要求已对齐）→ FWHM 5.51 px vs 单帧 3.34 px，**−65%**。这不是回归，正是"输入未对齐"的必然结果；drizzle 分支把它救回来了。

### 采样增益到底有多少

8 帧干净子帧、×2、p=1：

| 配置 | FWHM（本机口径） |
| --- | --- |
| 单帧原生 | 2.89 px |
| 单帧 → drizzle ×2 | 3.06 px（= 理论盒式模糊 2.97，实测吻合） |
| 8 帧 → drizzle ×2 | 3.06 px（**与单帧完全相同**） |
| 8 帧 → drizzle ×2, p=0.7 | 3.02 px |
| 8 帧 → drizzle ×2, p=0.5 | 2.98 px |

也就是说：**在这套数据上，叠加没有让 PSF 变窄，p=1 的盒式模糊还多花了 5.7%**。原因是 σ_psf 1.6–1.7 px（FWHM 3.8/2.9 px）**已经满足奈奎斯特**，按文章 7.4 节的表，3.0 px 的 FWHM 顶多换来 1.3% 的恢复；drizzle 的采样增益要在 FWHM≈1–1.5 px 的严重欠采样数据上才明显。

于是真实的收益是这三条，而不是"分辨率变高"：

1. **能吃未对齐输入**（原生路径直接糊 65%），把配准并进叠加器；
2. 输出网格 ×s 之后，**重采样不再二次加宽**（单帧 drizzle 只多一次 p=1 盒式模糊）；
3. 细节区落在更密的网格上，后续反卷积/展示有余量。

> 注：日志里"H 成品 3.34 px vs 单帧中位 3.81 px 改善 12.5%"是**与单帧中位**比，那是 PWS 空间加权的功劳，不是 drizzle 的；同一批帧走原生路径也有类似改善（前提是输入已对齐）。

## 六、已知限制（用之前请读）

1. **只做平移**，不支持旋转/缩放。同一次 session 内实测平移残差 0.10–0.22 px（相似变换拟合的旋转 ≤0.04°，scale 1.0000），所以平移是够的；**跨夜**混叠时可能有轻微旋转，靠边角的星会略微变胖（H 60 帧跨 11-01…11-05，中心 5.45 px、边角 5.94 px，边缘 +9%，其中有真实视场旋转的成分）。建议按夜/按 session 分组叠加。
2. **视宁度差的帧会拖宽翼部**。C 权重在 R≈1 的星核处压得极狠（C^20），但星翼的 R 低，S 权重只按噪声比，所以 FWHM 11 px 的烂帧仍会在翼部贡献。实测：只留 15 个锐帧 FWHM 3.06 px，全 60 帧 3.34 px。要"最锐"就用 `--limit` 或自己筛帧，要"最深"就全留。
3. **内存**：×2 时输出像素 4 倍；实现按输出行分带处理（band_h ≤512），峰值主要来自 memmap 帧缓存（60×2240×3072 float32 ≈ 1.5 GB）。
4. **`ν ≤ 1.10` 判据的数值会变**：输出像素更多、每像素帧数更少，N_eff 天然下降（H 28.35/60）。它是权重集中度的度量，不再等同于独立样本数。
5. **A=20 的标定**：星窗随 s 放大后，A 的物理含义（对比度→权重的陡度）不变，但如果你在原生网格上标定过一个"最佳 A"，换到 ×2 后建议重扫一次 15/20/25。
6. **p<1 有洞**：p·s < 2 时，若抖动不够均匀会出现未覆盖像素（实测 p=0.7 时 0.667% 的边缘像素无覆盖，但这是因为画布外框，不是抖动缺陷）。真实抖动不足时坚持 p=1。
